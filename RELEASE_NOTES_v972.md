# v0.7.97.2 — RPC: подтверждённые результаты и ускорение 04_CHECK

Сборка для проверки на Windows. PAPER — только после полного PASS 04_CHECK.
Распакуйте ZIP в новую папку, выполните 01_INSTALL, 02_SETTINGS, 04_CHECK.
Старую папку с данными и аварийными отчётами сохраните без изменений.

Свежий отказ v0.7.97.1: test_transient97_six_threads_remain_bounded_and_no_permanent_failures.
401 тест прошёл, один упал. Тест удерживаемых Windows handles прошёл: launcher и worker дали SIGNALED.
Причина первоначального RPC_CONTROL_RESULT_UNCONFIRMED не сохранена; конкретный WinError или блокировка SQLite этим архивом не доказаны.

Исправления:
- После проверки квитанции в контрольной БД отказ удаления не вызывает повторный stat/чтение той же квитанции. Windows delete-pending может запрещать и stat. Неучтённые файлы по-прежнему не удаляются.
- Временная конкуренция фонового читателя квитанций (SQLITE_BUSY/LOCKED, WinError 5/32/33) приводит к повтору уборки с сохранением файлов. Повреждённая/заменённая БД и другие ошибки сохраняют блокировку.
- Сценарий шести потоков сохраняет цепочки исключений, control_failed.json, диагностику уборки, сырые файлы контрольной БД и согласованную копию. Аварийный ZIP включает вложенный rpc_concurrency_v972.zip.
- Консоль выводит имя упавшего теста, а не только последнюю успешную фазу.

Оптимизация:
- 04_CHECK больше не повторяет 19 файлов тестов, уже успешно выполненных в текущем recovery. Весь прежний набор файлов сохранён. Если recovery падает, продолжения нет. Старые результаты не используются для пропуска новых проверок.
- В последнем Windows XML этим 19 файлам соответствуют 219 тестов, сумма их длительностей — 95,886 с. Это ориентир устранённой повторной работы, не измеренная гарантия ускорения нового запуска.
- Контроль SHA-256 читает каждый файл буфером 256 КиБ вместо загрузки целиком. Из поставки удалены промежуточные файлы сборки; рабочие исторические фикстуры сохранены. Изменённый файл с прежними размером и mtime по-прежнему блокирует запуск.

Сравнение files(1).zip:
Все три файла побайтно совпадают с ранее учтённым files.zip. В предоставленном скрипте и v0.7.97.1, и новый вариант проходят обычный отказ unlink, исчезновение файла и шесть потоков на Linux. Скрипт не содержит утверждений и не воспроизводит исходную Windows-причину.
Полная замена модуля откатила бы защиту: предложенный код удаляет неизвестный устаревший .tmp и снимает маркер по durable=True без идентификатора результата/БД. Эти поведения не перенесены. Идея безопасной отложенной уборки сохранена и усилена проверкой квитанции.

Общий RPC-лимит 6/с, 4 одновременных запроса, Retry-After, свежесть данных, производственные дедлайны, правила входа/выхода и учёт капитала не изменены. Завершение позиций не имитируется.
Windows-проверка этой сборки и актуальные RPC/AMM здесь не подтверждены.
