# v0.7.99.2 — корректная проверка keep-alive при локальной отсрочке

По Windows-отчёту v0.7.99.1: 514 тестов прошли, один отказ, 312,06 с из 600. Предыдущие исправления подтверждены результатами тестов: 18 проверок чтения RPC-результатов, 21 проверка публикации статуса, шестипоточный стресс RPC. Recovery и acceptance согласованно отмечают отказ.

## Причина нового отказа

В `test_transport99_one_connection_per_thread` один поток получил `Deferred: LOCAL_RPC_STATE_LOCKED` до отправки HTTP. Другие потоки отправили 4 запроса через 2 соединения. Общее тестовое ожидание допуска — 100 мс (conftest), рабочее — 750 мс. Прежний тест ошибочно требовал немедленного допуска для всех шести чтений.

Точный источник конкуренции по приложенному трейсбеку не установлен: поле control_v95 с фазой и цепочкой в тексте этого отказа не сохранено. Само имя STATE_LOCKED не доказывает конкретную блокировку SQLite или дефект keep-alive. Ошибка WinError 10053 в stderr относится к локальному HTTP-серверу тестов; она не является указанной причиной отказа теста и не относится к соединению с провайдером.

## Что исправлено

Исправлен только тест и сбор диагностических доказательств. Код RPC-регулятора, HTTP-транспорта, обработки отказов чтения, свежести банка, STOP и торговые правила не менялись.

* Перед каждым логическим чтением тест допускает возврат локального Deferred и повторяет попытку через настоящий общий RPC-допуск. Окно таких повторов ограничено 10 с для тестового задания. Тестовые 100 мс на один допуск и рабочие 750 мс не увеличены. При неразрешённой конкуренции тест всё равно завершается отказом, сохраняя последние восемь причин/стадий.
* Успех требует всех 6 HTTP-запросов и ровно 3 соединений. Дополнительно проверяется, что два чтения каждого потока используют один и тот же объект соединения, а у трёх потоков объекты различаются. Ссылки удерживаются до проверки, поэтому повторное использование адреса освобождённого объекта не может дать ложный успех.
* Повтор касается только локального отказа до HTTP. HTTP 429, сетевые ошибки и прочие исключения не повторяются этим тестовым планировщиком.
* Добавлены пять обязательных моделей: отсрочка перед первым запросом, отсрочка при прогретом соединении, постоянная отсрочка до дедлайна, отсутствие повтора HTTP 429 и отсутствие подавления других ошибок. Модели отсрочки сохраняют настоящий RPC-регулятор для всех фактически отправленных запросов.
* Recovery сохраняет три набора доказательств 6 запросов / 3 соединения в `transport_thread_evidence_v992`, проверяет их вместе с пятью новыми тестами и синхронно записывает acceptance. План по-прежнему содержит 39 recovery-файлов, 54 последующих технических файла; 19 повторных запусков файлов исключены.

Воспроизведение с одинаковой искусственной локальной отсрочкой: прежний тест v0.7.99.1 падает, исправленный v0.7.99.2 проходит с реальными 6 запросами и 3 соединениями. Это модель на локальном HTTP-сервере, не измерение текущего RPC провайдера и не подтверждение TLS/AMM/live.

## Запуск

Распаковать целиком в новую папку, например `C:\pumpbot\pumpfun_bot_v0.7.99.2_transport_check`. Старые папки и отчёты сохранить.

1. `01_INSTALL.bat` → `02_SETTINGS.bat`.
2. `04_CHECK.bat`, дождаться полного PASS. Проверка Windows/Python 3.14 обязательна на вашем ПК. Лимит офлайн-набора остаётся 600 с.
3. После PASS — `03_START.bat`, только PAPER.
4. После штатной остановки — `05_RESULTS.bat`.

Keep-alive включён; кэш genesis по умолчанию выключен (`GENESIS_CACHE_TTL_S=0`). Общие лимиты RPC, стратегия, капитал, учёт расходов и рабочие дедлайны сохранены. Дорожная карта и раздельные Curve/AMM-счётчики остаются на обеих страницах панели. Рост памяти, задержки реального выхода и текущий AMM-выход этой проверкой не оцениваются.

`12_NETWORK_CHECK.bat` запускается отдельно после штатной остановки бота: провайдер допускает один WebSocket. При сборке использовался только локальный тестовый сервер; подключения к провайдеру не выполнялись.
