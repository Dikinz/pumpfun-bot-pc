Первая целевая оптимизация — проверить единый keep-alive-транспорт для живого getGenesisHash и добавить такие же метки транспорта, сохранив проверку идентичности сети. Объединение VERSION_CHECK с банком требует отдельного доказательства сохранения последовательности проверки, не механического уменьшения числа RPC.

## Работа над v0.7.100 и критерии приёмки

| Порядок | Изменение | Критерий приёмки |
|---|---|---|
| 1 / P0 | После отрицательной проверки остатка интервалы 10 → 30 → 60 → 300 с, ускорение по новому принятому событию того же mint с защитой от частых повторов; не более одной пробы на 2 с по ветке | Интервалы сохраняются после рестарта; новое событие будит пробу; другие mint не будят; технический cooldown и общий RPC-лимит сохраняются; капитал и слот освобождаются только после допустимой продажи |
| 2 / P0 | Genesis переведён на тот же keep-alive, метки транспорта для каждой попытки; live genesis по умолчанию, TTL=0 | Локальный HTTP/1.1-тест: accounts → genesis → accounts использует один сокет и три допуска; 429 сохраняет общий cooldown; на Windows видны transport/reused-метки. Прирост медианы/p95 подтверждается только следующим сопоставимым прогоном |
| 3 / P0 | Stressed equity, явный счётчик отказов по слоту при остатке, отчёт корзин времени | Старые/неполные резервы дают UNKNOWN, не номинал позиции; деньги и net не меняются; повторный trade_id не увеличивает счётчик; знаменатели одобрений видны |
| 4 / P1 | AMM-сценарий по умолчанию выключен; ROUTE сохранён | OFF запускает только ROUTE; при старых открытых AMM-позициях запуск с OFF блокируется явной причиной; ON включает прежние две ветки. Целевой тест мигрировавшего mint должен дать проверенную локальную AMM-продажу, а не TICK_FALLBACK |
| 5 / P1 | Классы расходов, отдельная модель постоянного кошелька; секундный OHLC от сигнала до fill | Строгие ledger/cash не изменены; рента/повторное использование имеют условия; бары ограничены 200 на позицию, пропуски и смена процесса явны, цена не выдаётся за исполнимую |
| 6 / P1 | JSON-only review_bundle, хеши и created_ts отчёта в имени, БД отдельными томами | CRC и SHA256 всех включённых файлов; нет БД внутри review_bundle; оригиналы не меняются; отсутствующий timestamp явно UNKNOWN. Исходная preservation сохраняется |
| 7 / P1 | CreateProcessW — причина пока UNKNOWN | Сопоставимые трассы вызова и Process Monitor с PID/временем/результатом. Обычный read-only 13_SPAWN_DIAGNOSTICS не считается причинным экспериментом. Постоянный пул не внедрён без отдельной проверки владения/очистки Job Object |

Новая сборка требует своего 04_CHECK на Windows. Офлайн-тесты Linux не подтверждают Windows API или текущий RPC. Исторический fixture не заменяет целевой AMM-тест. Торговые пороги и бюджет 6 запросов/с, 4 in-flight не меняются. Бессрочный genesis-cache, склейка банков, hedging и пул процессов в этот патч не входят.

Для следующего короткого теста механики сначала подтвердить самопроверку, затем смотреть интервалы проб, сетевые метки и причины просрочек. Продлевать прогон ради 100 закрытий при неустранённом отказе не нужно. При условном темпе 2,2 закрытия/ч 100 с нуля — около 45,5 ч; после 11 остаётся около 40,5 ч, но темп не гарантирован. Интервалы win rate Wilson 95% для 4/11 и 1/10 широки (приблизительно 15–65% и 2–40%); прибыльность ими не доказана.

Данные пересчёта: `verified_findings_v100.json`. Большой архив повторно присылать не требуется.
