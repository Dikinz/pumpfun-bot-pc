# v0.7.101.1 — независимое ревью и регрессии

Стратегия, торговые пороги, свежесть данных, общий RPC-лимит и финансовый журнал сохранены.

Исправлены три воспроизведённые ошибки v101:

1. Отказ перечисления outcomes больше не выглядит пустой папкой. Строгое чтение каталога откладывает новые RPC, сохраняет исходную цепочку ошибки и не разрешает аудированное восстановление при неизвестных результатах. После восстановления доступа отложенный 429 применяется с исходным Retry-After. Дашборд показывает OUTCOME_READ_BUSY; существующий BLOCKED сохраняет приоритет.
2. Контролируемый PAPER-тест считается завершённым только после штатного запроса STOP его таймером. Ручная ранняя остановка с долгим завершением остаётся INCOMPLETE_OR_FAILED.
3. verified_exits в лёгком API ROUTE снова число. Сырые settlement details не экспортируются в /overview; модель постоянного кошелька получает последовательность строк без промежуточного полного списка.

Добавлены пятнадцать регрессионных сценариев: отказ открытия/итерации каталога, запрет восстановления при неизвестных результатах, сохранение 429/cooldown и лимитов, ранний/таймерный STOP, небольшая/наполненная ROUTE-БД, доступность metadata.lock и всех слотов другому владельцу во время ожидания повтора. Все включены в 04_CHECK без дублирования recovery-файлов.

Нативные Windows-проверки, текущий RPC провайдера, физический двухчасовой PAPER-прогон и текущий AMM-выход проверяются отдельно. Офлайн-агенты их не подтверждают. Точная причина исходного Windows-отказа доступа остаётся неизвестной.

Порядок установки и переноса полной остановленной app/data сохранён из RELEASE_NOTES_v101.md. Используйте новую папку; не смешивайте файлы версий и не удаляйте control_failed.json. Затем 04_CHECK, 14_RPC_STATUS и обычный 03_START либо контролируемый 15_PAPER_FAULT_TEST. Перед сетевой проверкой остановите бота штатно: провайдер разрешает одно WebSocket-соединение.

Повторный раунд критика: неизвестные счётчики RPC сохраняются как null и не доказывают возобновление запросов. Отчёт хранит статус и достоверность трёх наблюдений. Поздняя ошибка чтения outcomes проходит через единый обработчик сводки с сохранением BLOCKED и исходной цепочки ошибки.
