PUMPFUN BOT v0.7.62 CLEAN
Полная самостоятельная PAPER-сборка. Это не набор файлов для замены.

ПЕРВЫЙ ЗАПУСК
1. В окне прежнего бота нажмите Ctrl+C и дождитесь завершения. Закройте старую
   вкладку панели. Старые папки и базы сохраните; новая сборка их не удаляет.
2. Распакуйте архив в НОВУЮ папку, например Desktop/pumpfun_bot_v0.7.62_clean.
   Не распаковывайте поверх v0.7.56/61. Не переносите .py, .venv, .env или app/data.
3. Откройте именно новую папку и выполните 01_INSTALL.bat.
   Создаётся локальная .venv. Глобальный Python и другие установки не изменяются.
4. 02_SETTINGS.bat: введите необходимые API/RPC-настройки заново.
   Ключи подписи кошелька не нужны. Старый .env автоматически не импортируется.
5. 04_CHECK.bat, затем 03_START.bat из этой же папки.
6. Новая панель: http://127.0.0.1:8188 — версия v0.7.62.
   На старом 8187 может оставаться страница/сервер прежнего бота. Он не используется.
   В окне старта напечатаны версия, папка и точный адрес новой панели.

ИЗОЛЯЦИЯ СБОРКИ
- Все BAT запускают собственный .venv/Python и bootstrap по абсолютному пути,
  в изолированном режиме Python. Унаследованные PYTHONPATH/PYTHONHOME не применяются.
- До загрузки бота проверяются SHA-256 файлов релиза: смешанный/изменённый/неполный
  набор модулей останавливается до запуска. После ручного изменения кода распаковать
  новую чистую копию. Настройки .env, данные и результаты не входят в эти хеши.
- .env читается только из app этой установки; родительский/чужой .env не ищется.
- Новая база app/data/clean_0762.db. Ссылка на другую/старую базу блокируется.
  В архиве нет баз, личных ключей, .env и установленного окружения.
- У каждого сценария собственные 30 PAPER и ноль позиций при первом запуске.
  Последующий запуск этой же папки продолжает её кампанию, не сбрасывает деньги.
- Занятый порт 8188 или общий предохранитель старого работающего бота блокируют
  запуск с PORT_IN_USE. Новая сборка сама не завершает процессы других версий.
  Остановить старый бот в его собственном окне, затем повторить 03_START.
- Панель сверяет версию, идентификатор базы и токен текущего запуска, прежде чем
  открывать браузер. Просто чужая страница на порту не считается успешным стартом.

ГРАНИЦЫ ТЕСТА
Пороги стратегии, часы и правила свежести не менялись. Primary — тиковый контроль;
ROUTE самостоятельно закрывает по свежей проверенной Curve/AMM-симуляции.
Успешные старые проверки не закрывают текущую позицию. Неликвидный остаток остаётся
открытым; расходы учитываются, слот освобождается однократно после закрытия.
Watchdog использует PID рабочего процесса из подтверждённого стартового сообщения,
а не PID Windows-обёртки. Чужая сессия/процесс и устойчивое зависание остаются ошибками.

Короткий тест: 20–30 минут, раньше остановить при техническом отказе.
Ctrl+C, дождаться завершения, выполнить 05_RESULTS.bat. Отдельно проверить
подтверждение primary и обеих веток. После остановки открытые позиции не управляются.
06_AMM_CHECK.bat — отдельная целевая локальная AMM-проверка без отправки транзакций.
Прибыльность, Jito, live и многочасовая устойчивость этим релизом не подтверждены.
Локальные проверки выпуска: VALIDATION_v62.json. Нативный Windows-тест предстоит.
