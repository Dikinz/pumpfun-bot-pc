QA добавил детерминированный тест конкурентного захвата metadata.lock и всех четырёх слотов во время ожидания повтора после PRIORITY_READ_BUSY. Он проверяет реальное чередование через Event, отсутствие удерживаемых блокировок и нулевой started без допуска HTTP. Новый тест включён в обязательный recovery.

Первый полный прогон исправленного кандидата выявил две ошибки маркировки версии dashboard/details.html. После исправления полный набор повторён целиком и прошёл. Незавершённые ранние прогоны не считались подтверждением. Для итогов использованы завершённый JUnit, код возврата процесса и JSON recovery; текстовые логи в этой среде могут показывать устаревший хвост.

Окружение: Linux x86_64, Python 3.12.14, pytest 8.4.2. Пропуски относятся к нативным Windows-проверкам и несовпадению PID namespace с procfs. Нативные Windows 3.14, реальный провайдер, внешний WebSocket и физический 2–3-часовой PAPER-прогон не проверялись; соответствующие флаги остались false.

Воспроизведение из app отдельной чистой копии с установленными requirements:

```bash
python -m pytest -vv --junitxml=full.xml
python -u recovery_selftest.py
```

Авторитетные материалы: green_full.xml, green_full_summary.json, green_recovery_check_v89.json, green_recovery_summary.json, green_acceptance_v90.json. Фактический последний полный запуск использовал внешний диагностический run_with_watchdog.py с -vv -s --full-trace; он не меняет код приложения и не ослабляет проверки.
