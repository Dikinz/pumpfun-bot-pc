# v0.7.99 — публикация статуса и проверенные RPC-патчи

Сборка для нового PAPER-теста. Предыдущие исправления v0.7.98 сохранены.

## Исправлено падение PRIMARY при записи диагностического статуса

`MonitorWatch.sample` отделяет свежее чтение heartbeat от публикации JSON. Исчерпанные ошибки записи статуса не завершают основной цикл: в SQLite, журнале и обеих страницах панели появляется `MONITOR_SUPERVISION_PUBLICATION_FAILED`. Сохраняются тип, errno, WinError, стадия записи, число попыток, места стека и цепочка исходной ошибки. Произвольные сообщения исключений не записываются, поскольку они могут содержать ключи RPC. Причина отказа ОС/антивируса по этим кодам не считается установленной.

Общий `runtime_control.atomic_json` использует строгий `state_io`: четыре попытки замены с суммарной паузой 35 мс для WinError 5/32/33. Ошибки STOP и управляющих команд по-прежнему распространяются вызывающему коду. Подавление применяется только к диагностической публикации и только для OSError. Ошибка удаления временного файла не маскирует исходную. При недоступном удалении публикация удерживает один временный файл, не создаёт новый на каждом тике и после освобождения пишет последнее наблюдение. Старый JSON не становится свежим heartbeat.

`05_RESULTS` включает JSON статуса и ограниченный журнал state_io, в том числе предыдущий файл ротации. В общую диагностику необработанного отказа добавлена исходная цепочка исключений.

## Патчи из пользовательского files(2).zip

Оригинал сохранён как `review_input/USER_PATCHES_v99.zip`, результат запуска приложенного скрипта — `validation/USER_SCRIPT_v99.json`. Скрипт прошёл, но использует подмены SDK и RPC-регулятора; это не доказательство работы настоящего SDK или провайдера.

* Keep-alive адаптирован в `app/rpc_transport_v99.py`. По одному HTTPS-соединению на поток, привязка к полному URL и PID, закрытие при смене адреса/ошибке/ответе Connection: close. Автоматических повторов HTTP и переходов по redirect нет. Общий RPC-допуск действует на каждый запрос; 429 и Retry-After сохраняются. Таймаут 6 с и проверка TLS библиотеки не ослаблены. При настроенном HTTPS-прокси сохраняется прежний путь urllib.
* `RPC_KEEPALIVE=1` включён по умолчанию. Для сравнения можно установить 0. Он переиспользует соединения между запросами внутри рабочего процесса; постоянный пул процессов этим патчем не создаётся. Ускорение реального прогона предстоит измерить.
* Необязательный кэш genesis адаптирован в `app/program_cache.py`. Исправлены общий временный файл, гонка записи, неограниченное чтение и обработка реального `solders.ParseHashError`. Запись защищена блокировками потоков и процессов, максимум 8 адресов, размер чтения до 32 КБ, ключ URL — SHA256. Неуспех записи не заменяет проверенный ответ живого RPC ошибкой кэша.
* `GENESIS_CACHE_TTL_S=0` по умолчанию: живой getGenesisHash остаётся обязательным. Опциональный диапазон 1–21600 с предполагает, что URL не переключат на другую сеть в пределах TTL. Это не свежая проверка идентичности сети. Бессрочный кэш не включён.

Объединения VERSION_CHECK с FRESH_TRADING_BANK в присланном патче нет. `capture_bank`, свежая проверка ProgramData после банка, общий RPC-бюджет и позиционный монитор не изменены. Порогов стратегии, резервов, учёта расходов и освобождения капитала эта версия не меняет.

## Проверки и запуск

В обязательный `04_CHECK` добавлены 21 проверка публикации/STOP и 30 проверок транспорта/кэша. На Windows тест удерживает настоящий файловый handle без FILE_SHARE_DELETE; здесь тот же отказ проверяется моделью. Транспорт проверяется локальным HTTP-сервером с настоящим RPC-бюджетом и solders. Это не тест текущего HTTPS RPC провайдера. Полные результаты среды сборки находятся в `validation/*v99*`; Windows-флаги здесь остаются false.

1. Распаковать весь ZIP в новую папку, например `C:\pumpbot\pumpfun_bot_v0.7.99_monitor_publication`. Не копировать поверх старого прогона и не удалять старые результаты/БД.
2. `01_INSTALL.bat`, затем `02_SETTINGS.bat`. Использовать прежние публичные настройки RPC/источника и Jupiter API key; приватный ключ кошелька не требуется.
3. Запустить `04_CHECK.bat`. В нём recovery и acceptance обязаны согласованно пройти на этой Windows-машине. Весь офлайн-набор имеет лимит 600 с; рабочие таймауты не увеличены. Проверки не дублируются между recovery и последующей технической фазой.
4. После PASS — `03_START.bat`, только PAPER. Сначала контролировать предупреждение публикации, STOP и расходы RPC, затем задержки preentry. После остановки — `05_RESULTS.bat`.
5. `12_NETWORK_CHECK.bat` запускать только после штатной остановки бота: провайдер допускает один WebSocket. Живого сетевого теста при сборке не было.

На обеих страницах панели сохранены дорожная карта и отдельные Curve/AMM-счётчики. Текущий подтверждённый AMM-выход этим релизом не заявляется. Для целевого теста остаются существующие AMM-инструменты; историческая офлайн-проверка не подтверждает текущий RPC.
