# v0.7.100 — RPC, остатки и проверяемый экспорт

Новая папка: pumpfun_bot_v0.7.100_rpc_remainder. PAPER, порт 8188.

Внедрено:
- OPEN_REMAINDER: после валидного отрицательного результата интервалы возрастают до 30/60/300 с (обычный начальный — 10 с). Принятое новое событие того же mint будит пробу; защита от повторов — 2 с, общая частота остаточных проб ROUTE — максимум одна за 2 с. Лимит всех RPC 6/с и 4 in-flight, технический cooldown, ownership и freshness не меняются. Изменение inventory/wallet/epoch отменяет старую политику. Подтвердившее достаточные резервы чтение по-прежнему требует полной свежей симуляции перед продажей.
- PROGRAM_CACHE_GENESIS использует общий keep-alive с ACCOUNT-стадиями. DISCOVERY уже использовал его, но первый запрос в новом процессе остаётся холодным. Genesis остаётся живой проверкой сети; GENESIS_CACHE_TTL_S=0. Нового объединения банков, hedging или пула процессов нет. Ускорение сети пока не измерено.
- На обеих страницах dashboard сохранена шкала дорожной карты. Добавлены stressed equity (только доказательства не старше 5 с, иначе UNKNOWN), нулевая выручка остатка и счётчик DISTINCT PRIMARY-входов, отклонённых локальным slot gate при удержанном остатке. Это не доказанная потеря прибыли: другие гейты для этих входов не оценивались.
- Строгие расходы сохранены. Рядом выводится отдельная чувствительность постоянного кошелька: первое создание volume PDA оплачено для каждой программы; ATA удержаны / условно закрыты пустыми. Это модель с допущениями, не фактический возврат ренты или прибыль кошелька.
- AMM_BRANCH_ENABLED=0 по умолчанию отключает дополнительный AMM/TICK_FALLBACK-сценарий. PRIMARY и ROUTE работают; проверка Pump AMM внутри ROUTE сохранена. Если в существующей AMM-БД открытые позиции, OFF блокирует запуск с явной причиной, чтобы не оставить их без управления. Верните AMM_BRANCH_ENABLED=1 и разберите старую кампанию до отключения; файлы не удаляйте.
- Ценовой путь после сигнала сохраняется в exit audit: секундные OHLC, максимум 200 баров на активную позицию, счётчик вытеснения, отдельные сегменты процесса. Нет записи каждого сообщения в БД; используется существующий checkpoint раз в 5 с и финальный fill. Отсутствующие тики не интерполируются и не считаются исполнимыми ценами.
- run_review_v100.json: все входы и сценарий нулевой выручки, PRIMARY fill против снимков открытых ROUTE-позиций, корзины длительности preentry с явным знаменателем и error_code/error_name неудачных BUY.
- Разрывы discovery: отдельные observed boundaries и длительность wall clock, NULL при обратном скачке часов. Потерянные у провайдера кандидаты остаются неизвестными. Время завершённого subscribe не является подтверждением поступления всех пропущенных событий.
- 05_RESULTS сохраняет полный каталог доказательств и исходную preservation. Компактные review_bundle_*.zip содержат только JSON и SHA256-манифест. Имена вложенных JSON берут timestamp отчёта (created_ts при наличии), не дату экспорта. Неизвестная дата не подменяется. Тома около 8 MiB максимум, кроме явно отмеченного одиночного большого отчёта. БД/WAL/SHM и согласованная копия каждой БД отдельно: raw_database_volumes/raw_db_*.zip. Старый единый большой ZIP не создаётся; dashboard.html и подробные диагностические ZIP лежат в полном каталоге.

Проверка перед запуском:
1. Распаковать в новую папку. Можно выбрать C:\pumpbot\pumpfun_bot_v0.7.100_rpc_remainder. Старую папку и результаты сохранить. Автоматические исключения Defender и повышение прав не выполняются; причина прежних WinError 5 / CreateProcessW не установлена.
2. 01_INSTALL, 02_SETTINGS (публичные API-ключи; никаких private keys), 04_CHECK. 600 с относятся к офлайн-набору, а не к производственным дедлайнам. Повторные тестовые файлы по-прежнему исключаются планом; все исходники проверяются SHA256 перед каждым запуском без кэша по mtime.
3. После PASS — 03_START для короткого теста механики. Смотреть реальные transport/reused-метки, p50/p95, интервалы проб, slot exclusions и сетевые ошибки. Снижение latency/RSS заранее не обещано.
4. Штатно остановить Ctrl+C один раз, дождаться писателей. 05_RESULTS. Для разбора сначала отправить review_bundle_*.zip и его manifest; БД — нужными raw_db-томами отдельно. Полную preservation не удалять.

Целевая AMM-проверка:
- Остановить бот штатно. 06_AMM_CHECK использует текущий RPC и локальную изолированную симуляцию с синтетическим балансом, ничего не подписывает и не отправляет в сеть, WebSocket не открывает.
- Указать публичный mint действительно мигрировавшего canonical Pump AMM-пула, целое положительное raw_amount и decimals, проверенные по mint. Произвольные цифры не проверяют жизненный цикл реальной позиции.
- Смотреть app/data/target_amm_check_v59.json (CURRENT_RPC_ISOLATED_SIMULATION), passed/decision, pool/slot/snapshot_received_ts и evidence ZIP. Исторический fixture из 04_CHECK не является результатом этого теста. Даже PASS целевого изолированного теста не закрывает пункт дорожной карты о фактически исполненном ROUTE-выходе с освобождённым слотом.

CreateProcessW:
13_SPAWN_DIAGNOSTICS собирает существующие трассы и доступные события Windows только для чтения. Для причинного разбора нужен отдельный сопоставимый эксперимент: Process Monitor с фильтром по фактическому Python PID/пути, Process Create, Load Image, CreateFile, ACCESS DENIED и отметками времени из child_lifecycle. Сравнивать одинаковые проверки и холодный/тёплый запуск. Корреляция с AV не доказывает причину; настройки защиты не изменены. Пул воркеров не добавлен: он требует отдельной проверки Job Object, владения handles, STOP и восстановления при неопределённом запуске.

Нативные Windows API и текущий провайдер должны проверяться на целевой машине. В сборке нет ключей, чужих торговых БД, готового Windows PASS или разрешения live. Торговые пороги сохранены.
