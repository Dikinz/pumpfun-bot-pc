# P0.1–P0.2 — критерии регрессии

Согласованы 10 с и 16 с. Автоперезапуск отключён.

| Требование | Проверка |
|---|---|
| T1.1 / T1.3 | Настоящий main.run, два worker, выход выбранного worker кодом 0; heartbeat primary продолжается, другая ветка жива, PAPER-позиция закрывается |
| T1.2 / T1.3 | Worker завершает процесс и закрывает читающий конец реального pipe; запись вызывает ошибку, sender прекращается, unsent/delivery_uncertain/dropped учитываются |
| T1.4 | Отсутствующая ветка и явный BRANCH_UNAVAILABLE в matched_lots; неполная пара не допускается в сравнение |
| T1.5 | Первичная ошибка останавливает ветки с PARENT_STOP; позиция восстановлена как carried |
| T2.1 | Настоящий зависший процесс, WORKER_TIMEOUT после 10 с; общий срок нормальной очистки <=11 с |
| T2.2 | Настоящий monitor_service, две позиции, зависшая первая; вторая проверяется трижды с интервалом 10±3 с, без MONITOR_LOOP_GAP/MISSED_CHECK; heartbeat <=11 с |
| T2.3 | Подтверждение очистки, отдельный native Windows worker с потомком; до/после снимки дерева процессов и integrity_check временных БД |
| T2.4 | Неподвижный pulse на 20 с; primary-наблюдатель объявляет MONITOR_NOT_RUNNING на 16 с, сохраняет снимок/возраст |
| T2.5 | STARTED_BEFORE_SIGNAL сохраняется; WORKER_TIMEOUT остаётся техническим исходом; существующие тесты session/epoch/recovery и нового разрешённого задания также включены |

Для каждой P0-проверки открыта позиция 3 PAPER; для справедливости scheduler —
две позиции. Финансовые записи выполняет настоящий PAPER-учёт.

Критерий приёмки не закрыт до зелёного 04_CHECK на Windows Python 3.14 и одного
рабочего прогона >=2 часа с контролируемым отказом ветки в середине.
Пропущенные native-тесты Linux не заменяют приёмку Windows.
Управляемый STOP и неожиданный выход — разные инъекции. Для управляемого STOP
проверяются session/PID и время исходного запроса: ранний ack не должен стать
ложным UNCONFIRMED. Неожиданный выход без ack не считается штатным завершением.
