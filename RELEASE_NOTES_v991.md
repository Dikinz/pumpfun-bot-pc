# v0.7.99.1 — исправление двух отказов Windows-самопроверки

Изменения основаны на recovery v0.7.99: 495 тестов прошли, два завершились отказом за 304,81 с при лимите 600 с. Recovery и acceptance согласованно фиксировали отказ. Все 21 тест публикации статуса прошли. Полный исходный архив и предоставленные пользователем отчёты не изменялись.

## 1. Ошибка имени теста, а не проверки кэша

У параметра с данными 33 000 символов pytest автоматически создал имя длиной 33 070 символов. При setup pytest записывает имя в PYTEST_CURRENT_TEST; Windows отказала: `ValueError: the environment variable is longer than 32767 characters`.

Для четырёх случаев кэша заданы короткие явные IDs: invalid-json, array, oversized-33kb, invalid-record. Содержимое тестовых файлов и проверки кэша не сокращены. Сопоставимый запуск с моделью ограничения Windows воспроизводит один отказ в v0.7.99 и четыре успешных случая в v0.7.99.1; максимальная длина имени среди этих четырёх случаев стала 84 символа.

## 2. Недоступное чтение RPC-результата

В неизменённом стресс-тесте шести потоков чтение `_event` → `Path.read_text` → `open` получило `PermissionError`, errno=13. WinError отсутствует. Все потоки и уборщики завершились, control.db прошла проверку целостности, control_failed.json не был создан. Точная внешняя причина отказа доступа не установлена: блокировку SQLite, антивирус или конкретную гонку удаления считать доказанными нельзя.

Прежде ошибка чтения превращалась в `RPC_CONTROL_IO_ERROR` и прерывала проверку. Теперь временная ошибка доступа/совместного доступа при чтении ещё не подтверждённого результата превращается в локальную отсрочку `OUTCOME_READ_BUSY`. Повтор выполняется после освобождения metadata.lock, только в пределах прежнего дедлайна RPC-допуска. Таймауты и общий лимит RPC не увеличены; скрытого повтора HTTP нет.

Неизвестный файл не пропускается и не удаляется, квитанция не предполагается существующей. До чтения и учёта результата новый HTTP не допускается. После восстановления чтения настоящий 429 учитывается ровно один раз и сохраняет Retry-After/cooldown. Для уже подтверждённой квитанции остаётся прежний безопасный путь без повторного открытия файла. Повреждённые данные и невременные ошибки диска по-прежнему приводят к отказу.

Точная цепочка типов, errno/WinError и мест стека сохраняется в `outcome_read_v991.json`, в телеметрии отсрочки и в RPC-архиве `05_RESULTS`. Произвольные сообщения исключений, URL и ключи не сохраняются. Диагностический файл не является разрешением RPC; его запись ограничена одной записью в секунду на Budget/поток. Защита STOP и общая atomic_json не ослаблялись.

## Проверки

Добавлены 18 обязательных проверок: неизвестный/подтверждённый результат, стат/чтение, errno13 и WinError 5/32/33, сохранение 429, освобождение metadata/слота, сохранение исходной причины в экспорте, повреждение данных и невременный I/O. На Windows одна из них удерживает настоящий handle, запрещающий чтение файла. Здесь этот случай проверяется моделью; собственный запуск Windows/Python 3.14 не выполнен.

Прежний шестипоточный тест не удалялся, его 15-секундный дедлайн не увеличен. Прежние 21 тест публикации и 30 тестов транспорта/кэша остаются обязательными. Проверки recovery и acceptance привязаны к новой версии и включают новый блок тестов. Сводные результаты среды сборки — `validation/*v991*`; результаты Windows по-прежнему должен подтвердить 04_CHECK на вашем ПК.

Пороги торговли, учёт капитала/расходов, reserve hint, свежесть банка, приоритет выходов и рабочие дедлайны не менялись. Keep-alive из v0.7.99 сохранён включённым; `GENESIS_CACHE_TTL_S=0` по умолчанию. Бессрочный кэш genesis и слияние VERSION_CHECK с банком не включены. Дорожная карта и раздельные Curve/AMM-счётчики сохранены на обеих страницах панели. Снижение памяти и текущий AMM-выход этой версией не заявляются.

## Запуск

Распаковать ZIP целиком в новую папку, например `C:\pumpbot\pumpfun_bot_v0.7.99.1_rpc_read`. Старую папку, БД и аварийные ZIP сохранить.

1. `01_INSTALL.bat` → `02_SETTINGS.bat`.
2. `04_CHECK.bat`; дождаться PASS. Лимит всего офлайн-набора остаётся 600 с, дублирование 19 файлов тестов между фазами не возвращалось.
3. После PASS — `03_START.bat`, только PAPER.
4. После штатной остановки — `05_RESULTS.bat`.

`12_NETWORK_CHECK.bat` запускать отдельно, только после штатной остановки бота: провайдер допускает один WebSocket. Текущий RPC и WebSocket при сборке не проверялись.
