## Обязательные обходы (реализованы в `desktop/`)

1. **Короткий путь.**
   - Длинные пути ломали импорт даже при `LongPathsEnabled=1`:
     - `WebView2Loader.dll` (271 символ) и `Microsoft.Web.WebView2.WinForms.dll` (262) давали `FileNotFoundException`;
     - `_cffi_backend.pyd` (253 символа) давал «DLL load failed … имя файла слишком длинное».
   - Junction не помогает: .NET Framework считает такой путь сетевым (HRESULT 0x80131515). Короткие имена 8.3 тоже не помогают, потому что pywebview вызывает `realpath`.
   - Поэтому `paths.short_path_problem()` проверяет длину путей: до 259 символов для `.dll`, до 247 для `.pyd`. Путь через ссылку или junction отклоняется с ошибкой `DESKTOP_PATH_LINK`. `app_main` выполняет эту проверку до импорта pywebview.
2. **localStorage.** `webview.start(private_mode=False, storage_path=%LOCALAPPDATA%\PumpfunPaperDesktop\<identity>\WebView2)`. Без этого pywebview работает в приватном режиме по умолчанию.
3. **Сворачивание в трей.** `window.destroy()` тоже вызывает `closing`, поэтому нужен флаг `allow_quit`. Обработчик `closing` возвращает `False`, а `hide()` вызывает в отдельном потоке. «Выйти из окна» делает так: `allow_quit=True`, затем `icon.stop()`, затем `window.destroy()`.
4. **pystray.** `icon.run_detached()` вызывается до `webview.start()`. `webview.start` всегда работает в главном потоке.
5. **PID хоста движка.** `venv\Scripts\python(w).exe` — это прослойка, которая запускает настоящий интерпретатор, поэтому процессов два. PID берётся из `engine_state.json` (pid + create_time), а не из `Popen`.
6. **Журналы под pythonw.** Stdout нет, поэтому вывод окна пишется в `%LOCALAPPDATA%\PumpfunPaperDesktop\<identity>\window.log`.

## Режим разработки (только для тестов)

Переменная `PFDESK_DEV_DASHBOARD_PORT=<8210..8219>` направляет окно на тестовую панель вместо 8188. Любое другое значение — отказ запуска с сообщением. Только вместе с ней читаются:
- `PFDESK_DEV_DB` — база, чью `database_identity` должна сообщить панель;
- `PFDESK_DEV_CONTROL` — папка `engine_state.json`, стоп-файлов и журналов;
- `PFDESK_DEV_PROFILE` — база профиля WebView2 и `settings.json`.

Что меняется в этом режиме:
- в заголовке появляется метка `[DEV]`, на странице — баннер;
- проверка сборки (`release_guard` и `DESKTOP_EXTRA_MODULE`) пропускается;
- запуск движка, 05/04 и консоли 02/08 **отключены**.

На рабочей установке эти переменные не задаются.
