# Фаза 1: кошелёк и RPC

Цель: загрузка, права и подпись без отправки. Обычный PAPER не загружает
секрет кошелька и не вызывает подписывающий процесс.

Предложенный `Keypair.from_json(path.read_text())` читает открытый секрет.
Метод объекта `sign()` сам по себе не изолирует процесс. Здесь SecureWallet
хранит пути и публичный адрес. AES-GCM расшифровывается отдельным процессом.
Пароль проходит по stdin pipe, а не через argv, env или временный файл.
KDF: scrypt N=32768, r=8, p=1; соль 16 байт, AES-GCM nonce 12 байт.

На Linux проверяется владелец, запрещены права группы/остальных и симлинки;
файлы создаются 0600. На Windows создаётся защищённая DACL текущего пользователя,
SYSTEM и Administrators; широкие разрешения и наследуемые ACL отклоняются.
Windows-код требует проверки на реальном ПК. Администратор ОС не является
границей защиты. Отдельный процесс не является OS sandbox или hardware wallet.
Python не гарантирует обнуление всех копий памяти; завершение процесса
ограничивает время существования расшифрованного Keypair.

## Офлайн-проверка кода без своего ключа

Из корня распакованной сборки:

    .venv\Scripts\python.exe app\execution_lab.py check

Создаются временные случайные ключи; RPC-ответы имитируются. Проверка также
включена в 04_CHECK.bat. Никакие транзакции не публикуются.

## Проверка собственного кошелька локально, без отправки

Для PAPER это не требуется. Ключ и пароль вводятся только в локальном терминале.
Не присылайте их в чат, скриншоты или архивы.

    .venv\Scripts\python.exe app\execution_lab.py wallet-init
    .venv\Scripts\python.exe app\execution_lab.py wallet-check

Vault и политика находятся вне папки бота: ~/PumpfunBotPrivate/.
Существующие файлы не перезаписываются. Начальная swap-политика выключена:
enabled=false, список монет пуст. wallet-check работает без её включения:
ребёнок сам строит фиксированную memo-транзакцию с нулевым blockhash, который
не подходит для сетевой отправки. Передать произвольную транзакцию через этот
режим нельзя. Возвращаются публичный адрес, signature и результат проверки;
приватный ключ родителю не возвращается. RPC и broadcast не вызываются.

## RPC

rpc_client.RobustRPC использует одну aiohttp.ClientSession на async-контекст,
connection pool, тайм-аут и bounded retry. Закрытие контекста закрывает сессию.
HTTP redirects запрещены. Статистика содержит номера endpoint и коды, без URL.
Fallback — только для разрешённых методов чтения. Ошибки неверных параметров
не повторяются. Для отправки максимум одна попытка; потерянный ответ становится
UnknownSubmission, без переключения провайдера и повторной отправки.
Send по умолчанию запрещён; явное включение требует ожидаемый genesis hash.
Новый клиент относится к execution lab; поток PAPER и его существующая частота
RPC не переключаются автоматически в этой версии.

Опциональный сетевой probe: создайте защищённый JSON вне папки бота с полями
endpoints (массив HTTPS URL) и expected_genesis (ПОЛНЫЙ hash нужного кластера).
Не используйте сокращённый CAIP-2 идентификатор вместо полного genesis hash.
Права файла — 0600/защищённая DACL. Затем:

    .venv\Scripts\python.exe app\execution_lab.py rpc-probe C:\private\rpc_endpoints.json

Это реальные getGenesisHash/getSlot-запросы и расход квоты выбранного RPC,
но не отправка транзакций. Платный провайдер и Geyser не гарантируют landing;
Geyser является потоком данных, а не подтверждением исполнения.

Экспорт не обходит домашнюю папку: копирует только явно выбранный execution
journal SQLite и публичные отчёты. Vault, пароль, signer policy и RPC settings
в 05_RESULTS не включаются.
