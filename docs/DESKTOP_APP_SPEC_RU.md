
# ТЗ: настольное приложение Windows для PAPER-бота (MVP, вариант A)

Версия ТЗ: 1.0, 02.11.2026. Основа: `docs/DESKTOP_APP_PLAN_RU.md` (утверждён вариант A). Базовая сборка движка: v0.7.101.4 / RUN_REVIEW_V1014.

## 0. Цель и границы

Окно Windows (WebView2 через pywebview) вокруг существующего терминала `http://127.0.0.1:8188/`, значок в трее, запуск и корректная остановка кампании без консоли. Пользователь получает: запуск/подключение, состояние, остановку с подтверждением и прогрессом, «Результаты», «Проверка», «Настройки» и «Сохранить данные».

**Не входит в MVP:** изменения стратегии, `app/main.py`, монитора, веток, дашборда (`app/dashboard/**`), `release_guard.py`, формата results. Также не входят LIVE-режим, автообновление, автозапуск, подпись, служба Windows и встроенный CPython. Скомпилированный установщик тоже не входит: скрипт `.iss` готовится, но Inno Setup на этом ПК не установлен.

**Единственное допустимое изменение движка:** в `app/launcher.py` у `start()` появляется параметр `open_browser=True`, а вызов `webbrowser.open(...)` выполняется только при `open_browser`. Значение по умолчанию сохраняет текущее поведение `03_START.bat` и `15_PAPER_FAULT_TEST`. `bootstrap.py` не меняется (см. открытые вопросы).

## 1. Архитектура

Приложение состоит из двух независимых процессов. Окно никогда не владеет жизнью кампании.

```
16_DESKTOP.bat / ярлык
  └─ .venv-ui\Scripts\pythonw.exe -I desktop\app_main.py      ← процесс ОКНА (pywebview + pystray)
        │  запускает отсоединённо (CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP),
        │  stdout/stderr → файл журнала; ничего не ждёт по pipe
        ▼
  .venv\Scripts\python.exe -I app\desktop_engine.py run --token <32hex>   ← ХОСТ ДВИЖКА
        └─ launcher.start(stop_condition=<есть стоп-файл токена>, open_browser=False)
              ├─ dashboard/server.py (8188)  ├─ main.py (CTRL_BREAK)  ├─ monitor  └─ ROUTE
```

- **Обмен окно ↔ хост — только через файлы** в `app/data/desktop/`. Сокеты, именованные каналы и новые порты не используются.
  - `engine_state.json` — состояние, атомарная запись через `state_io.atomic_json`.
  - `stop_<token>.request` — запрос остановки.
  - `logs/engine_<YYYYmmdd_HHMMSS>_<token8>.log` — журнал хоста и всех его дочерних процессов, которые наследуют дескрипторы.
  - Подпапка не попадает в `sqlite_preserve`: он копирует только файлы верхнего уровня по allowlist. `release_guard` проверяет только `.py`, а `app/data` исключена.
- Хост запускается со **скрытой собственной консолью** (`CREATE_NO_WINDOW`). Поэтому существующая цепочка остановки работает без изменений: `CTRL_BREAK` идёт группе процессов `main.py`, монитор останавливается закрытием stdin. Проверяется на этапе 0 и автотестом (раздел 6.3).
- Из-за venv-редиректора PID из `Popen` ≠ PID хоста. Окно опознаёт хост только по `pid` и `create_time` из `engine_state.json` (psutil) и **никогда** не завершает процессы движка.
- Окно работает в отдельном окружении `.venv-ui`, созданном на том же Python 3.14. Зависимости — `desktop/requirements-desktop.txt` с закреплёнными версиями и хешами: pywebview, pythonnet, pystray, Pillow, psutil и транзитивные. Рабочий `.venv` и `app/requirements.txt` не меняются.

### 1.1 Контракт хоста движка (`app/desktop_engine.py`)

- **Импорты верхнего уровня — только stdlib.** Константы контракта (`SCHEMA='DESKTOP_ENGINE_V1'`, `CONTROL_DIR`, `STATE_NAME`, `STOP_TEMPLATE`, `PHASES`, `TOKEN_RE='[0-9a-f]{32}'`) импортируются окном как единственный источник правды.
- **CLI:** `desktop_engine.py run --token <32hex>`. Других команд и тестовых хуков нет.
- **`preflight()` зеркалит `bootstrap.main()` для `start`:**
  1. `release_guard.verify(ROOT)`;
  2. `sys.prefix == ROOT/.venv`, иначе `CLEAN_ENVIRONMENT_MISMATCH`;
  3. удалить `PYTHONPATH`, `PYTHONHOME`, `DATABASE_PATH`, `DASHBOARD_PORT`;
  4. `chdir(APP)`;
  5. `launcher.setup_env()`;
  6. `local_database(APP, config.DB) == APP/data/clean_0762.db`;
  7. `config.EXECUTION_MODE == 'paper'`, иначе `PAPER_ONLY`.

  Совпадение с bootstrap закрепляется тестом паритета.
- **Фазы `engine_state.json`:** `PREFLIGHT → STARTING → RUNNING → STOP_REQUESTED → STOPPED`, а также `FAILED`.
  - Поля: `schema, version, token, pid, create_time, phase, started_ts, running_ts, stop_requested_ts, finished_ts, exit_code, error_code, log_name`.
  - `RUNNING` записывается при первом вызове `stop_condition`: к этому моменту лаунчер уже запустил все процессы.
  - Когда появился `stop_<token>.request`, записывается `STOP_REQUESTED`, и `stop_condition` возвращает `True`. Дальше лаунчер штатно идёт по пути `KeyboardInterrupt` → корректная остановка → аудит SQLite.
  - После `launcher.start` записывается `STOPPED` с `exit_code`. При исключении записывается `FAILED` с `error_code` = тип исключения и текст `RuntimeError` не длиннее 200 символов: это фиксированные сообщения guard и лаунчера, ключей там нет.
  - Код завершения процесса хоста равен коду лаунчера.
- **Перед стартом:**
  - если в `engine_state.json` указан живой хост (`pid` + `create_time`), выйти с `ALREADY_RUNNING` и не трогать его файлы;
  - удалить свои устаревшие `stop_*.request`.

  Стоп-файл именуется по токену, поэтому старый файл не может остановить новый запуск.

## 2. Функциональные требования (окно)

### 2.1 Определение состояния (опрос каждые 2 с)

1. В `engine_state.json` активная фаза, и хост жив → **OWN_<фаза>**. Окно может остановить такую кампанию.
2. В `engine_state.json` активная фаза, но хост мёртв:
   - `/health` отвечает «нашим» ответом, и процесс панели — потомок мёртвого хоста (цепочка ppid через psutil, сверка `create_time`) → **ORPHAN_RUNNING**. Текст: «Управляющий процесс бота завершился, а процессы бота ещё работают. Запуск, 05, 04 и настройки недоступны, пока они не завершатся. Перезагрузите компьютер, затем запустите 09_RECOVERY_CHECK.» Запрещены запуск, остановка, 05, 04, 02, 08; разрешены терминал, журнал и папки. Значок красный, уведомление один раз;
   - `/health` «наш», но панель не потомок хоста (например, устаревший файл состояния и запуск через 03_START), или происхождение не определить → **EXTERNAL_SAME**;
   - иначе → **ENGINE_LOST**. Показать предупреждение: «Движок завершился без итога: см. журнал, затем 09_RECOVERY_CHECK / 05_RESULTS». Кнопку «Запустить» разблокировать только после подтверждения.
3. Иначе `GET http://127.0.0.1:<port>/health` с таймаутом 0,5 с:
   - `version` == версия из `BUILD_MANIFEST.json` и `database_identity` == `sha256(normcase(resolve(APP/data/clean_0762.db)))[:20]` → **EXTERNAL_SAME**. Бот запущен через `03_START.bat`: терминал показывается, «Остановить» недоступна с подсказкой «Ctrl+C в окне 03_START».
   - Ответ есть, но не совпал → **EXTERNAL_FOREIGN**: «На порту 8188 работает другая установка/версия». «Запустить» недоступна.
4. Иначе → **STOPPED**. Показывается итог прошлого запуска из файла состояния: код, время, журнал. Если прогон закончился сам (`STOPPED` с кодом ≠0 без запроса остановки из окна), уведомление «Бот остановился сам (код N). Откройте журнал.» и красный значок до подтверждения пользователем.

**Гистерезис.** Переходы, которые зависят от `/health` (EXTERNAL_SAME → STOPPED, ORPHAN_RUNNING → ENGINE_LOST), происходят только после двух промахов `/health` подряд. Любой ответ `/health` и любое изменение `engine_state.json` применяются сразу.

Окно отправляет на порт панели только `GET /health` и загружает терминал. Порт 49190 окно не трогает.

### 2.2 Главное окно

- Если бот работает (OWN_RUNNING, OWN_STOP_REQUESTED, EXTERNAL_SAME), окно напрямую загружает `http://127.0.0.1:8188/`, **без iframe**: так у терминала сохраняется собственный origin и localStorage вкладок.
- Иначе загружается локальная страница состояния `desktop/ui/status.html`, переданная через `html=`. Локальный HTTP-сервер pywebview не поднимается. На странице: фаза, PAPER-бейдж, версия, итог прошлого запуска, кнопки действий.
- Заголовок окна: `PumpFun PAPER v0.7.101.4 — <состояние>`.
- **Нативное меню pywebview:**
  - «Бот»: Запустить, Остановить…;
  - «Отчёты»: Результаты (05), Проверка (04), Открыть папку results;
  - «Сервис»: Настройки (02, консоль), Сохранить данные (08, консоль), Журнал, Открыть папку журналов;
  - «Окно»: Терминал, Состояние, Свернуть в трей.
- Каждое действие перед выполнением проверяется по матрице 2.4. Недоступное действие показывает диалог с причиной.
- **js_api** — фиксированный набор методов без строковых аргументов: `get_status, start, stop, run_results, run_check, open_settings, open_preserve, open_results_folder, open_logs, show_terminal`. Путей, команд и URL из страницы не принимает.
- Профиль WebView2: `%LOCALAPPDATA%\PumpfunPaperDesktop\<identity>\WebView2` (`private_mode=False`), чтобы вкладки терминала сохранялись. Настройки окна (геометрия, «уведомление о трее показано», режим консоли) лежат там же в `settings.json`. В `app/data` они не пишутся.
- Если WebView2 нет или pywebview упал при старте: MessageBox с инструкцией и предложением открыть терминал в системном браузере. Кампанию это не затрагивает.

### 2.3 Действия

| Действие | Как выполняется |
|---|---|
| Запустить | Проверить `.venv` (иначе «Запустите 01_INSTALL.bat»). Создать токен. Запустить хост отсоединённо с очищенным окружением: без `PYTHONPATH/PYTHONHOME/DATABASE_PATH/DASHBOARD_PORT/EXECUTION_MODE`. Других `PYTHON*` переменных не добавлять: окружение хоста и его дочерних процессов совпадает с запуском из 03_START (хост идёт с `-I`, а `main.py`, панель и монитор — без `-I`, и иначе унаследовали бы UTF-8-режим). Журнал читается построчно: UTF-8, при ошибке ANSI-кодировка системы. Ждать `RUNNING` + `/health` с индикатором фаз. Через 120 с — текст «Запуск идёт дольше обычного (проверки на большой базе).», ожидание продолжается; ошибка только если хост умер или фаза `FAILED`. При `FAILED` показать `error_code` и хвост журнала |
| Остановить… | Только OWN_RUNNING. Диалог подтверждения: «Корректная остановка, как Ctrl+C в 03_START. Займёт обычно до 1–2 мин. Не выключайте ПК». Диалог — системный `MessageBoxW` с кнопками «Да»/«Нет» (по умолчанию «Нет»), владелец — главное окно; пока он открыт, повторный вызов «Остановить» второй диалог не открывает. После «Да» создать `stop_<token>.request`. Окно прогресса показывает шаги и таймер: запрос записан → движок принял (`STOP_REQUESTED`) → панель остановлена (`/health` недоступен) → итог (`STOPPED`, код 0 — корректно, ≠0 — «см. журнал, выполните 05_RESULTS/09_RECOVERY_CHECK», строка `SQLITE SHUTDOWN AUDIT` из журнала). Через 180 с — «Остановка идёт дольше обычного», но **никогда не убивать процессы** |
| Результаты (05) | Только когда бот не запущен и других действий нет. `.venv python -I app\bootstrap.py results`, скрытая консоль, вывод в `logs/results_*.log`, окно журнала его читает. По `FULL EVIDENCE FOLDER:` или `PRESERVED EVIDENCE:` — кнопка «Открыть папку». Действие продолжается, даже если окно закрыть |
| Проверка (04) | Те же условия. `bootstrap.py check`, окружение как в `04_CHECK.bat` (`PYTHONUTF8=1`, `chcp 65001`). Коды: 0 — PASSED, 2 — «проверь время», остальное — FAILED; тексты как в 04_CHECK.bat |
| Настройки (02) | Только когда бот не запущен. Новая видимая консоль: `cmd.exe /c "<ROOT>\02_SETTINGS.bat"` (`CREATE_NEW_CONSOLE`). Ключи вводятся в консоли через getpass, окно их не видит |
| Сохранить данные (08) | Доступно всегда (работает со старой папкой). Видимая консоль с `08_PRESERVE_DATA.bat` |
| Открыть results / журналы | `os.startfile` на `ROOT/results` или `app/data/desktop/logs` |

### 2.4 Матрица доступности

- **Запустить:** только STOPPED (и ENGINE_LOST после подтверждения), без идущего действия.
- **Остановить:** только OWN_RUNNING.
- **Результаты, Проверка, Настройки:** STOPPED или ENGINE_LOST и нет другого действия.
- **ORPHAN_RUNNING:** только терминал, журнал и папки; запуск, остановка, 05, 04, 02 и 08 запрещены.
- **Сохранить данные, папки, журнал:** всегда.
- Одновременно выполняется не больше одного фонового действия (05 или 04).

### 2.5 Трей

- Значок pystray, 4 состояния: серый (остановлен), зелёный (работает), жёлтый (запуск или остановка, идёт действие), красный (FAILED, ENGINE_LOST, ORPHAN_RUNNING, EXTERNAL_FOREIGN, бот остановился сам). Своя иконка и AppUserModelID `PumpfunPaper.Desktop` у окна, на панели задач и в уведомлениях.
- Подсказка: `PumpFun PAPER — <состояние>`.
- Меню: Показать окно (действие по умолчанию, двойной щелчок); Состояние: … (неактивный пункт); Остановить бота…; Выйти из окна.
- Уведомления: однократно при первом сворачивании («Бот продолжает работать»), по завершении остановки, при ENGINE_LOST, при входе в ORPHAN_RUNNING, когда бот остановился сам, при долгом запуске и по завершении 05/04.

### 2.6 Закрытие окна, выход, единственный экземпляр, выход из Windows

- **Крестик:**
  - если бот работает (OWN или EXTERNAL_SAME) или идёт действие — `closing` отменяется, окно скрывается в трей;
  - иначе приложение завершается.
- **Трей → «Выйти из окна» при работающем боте:** подтверждение «Окно закроется, PAPER-бот продолжит работать. Остановить его можно, снова открыв приложение». Завершается **только процесс окна**. Стоп-файл не создаётся, процессы не трогаются.
- **Падение окна** кампанию не затрагивает. Повторный запуск подключается по 2.1.
- **Единственный экземпляр:**
  - именованный мьютекс `Local\PumpfunPaperDesktop_<identity>`;
  - второй экземпляр выставляет событие `Local\PumpfunPaperDesktop_<identity>_show` и завершается с кодом 0;
  - первый экземпляр по этому событию показывает и разворачивает окно.

  Одновременный запуск движка дополнительно блокирует lock-файл лаунчера.
- **Выход из Windows / завершение работы:**
  - скрытое окно верхнего уровня (`desktop/session_end.py`) получает `WM_QUERYENDSESSION`;
  - если состояние OWN_PREFLIGHT, OWN_STARTING или OWN_RUNNING: `ShutdownBlockReasonCreate("Идёт корректная остановка PAPER-бота")` и создание стоп-файла (корректная остановка начинается сразу). Если стоп-файл появился до `launcher.start`, хост бота не запускает и сразу пишет `STOPPED` с кодом 0 и `running_ts=None` (остановка до запуска);
  - пока идёт выход из Windows (режим сеанса после `WM_QUERYENDSESSION`), закрытие формы в неудерживаемых состояниях разрешается без тоста и без стоп-файла. Режим сбрасывается по `WM_ENDSESSION(FALSE)`, через 60 с без продолжения или при `STOPPED`;
  - `ENDSESSION_CLOSEAPP` (Restart Manager, не выход из Windows): окно закрывается, кампания не останавливается, хост продолжает работать;
  - после `STOPPED` — `ShutdownBlockReasonDestroy`;
  - `SetProcessShutdownParameters` с повышенным приоритетом, чтобы окно получало сообщение раньше других.

  **Ограничение (честно в README):** если пользователь выберет «Всё равно завершить», Windows прервёт процессы движка. Это равносильно аварийному завершению, дальше действует штатный путь 09_RECOVERY_CHECK и 05_RESULTS. Рекомендация: останавливать бота до выхода из системы. При EXTERNAL_SAME окно выход не блокирует.

## 3. Нефункциональные требования

- **Только PAPER.** Хост отказывает, если `EXECUTION_MODE != paper`. В интерфейсе есть PAPER-бейдж, LIVE-элементов нет.
- **Ключи.** Окно не читает и не показывает `app/.env` и ключи, не логирует окружение. Настройки — только через консоль 02.
- **Сеть.** Окно не открывает слушающих сокетов. Исходящие соединения — только на `127.0.0.1:<порт панели>`. Solana RPC и рыночный WebSocket не используются никогда.
- **Права.** Без прав администратора, без службы, без автозапуска, без изменений реестра, кроме деинсталлятора Inno (HKCU).
- **Движок не меняется,** кроме параметра `open_browser`. `release_guard` проверяет файлы при каждом старте хоста, а окно при запуске вызывает `release_guard.verify(ROOT)`: модуль только на stdlib, импортируется из `app/`.
- **Ресурсы.** В простое процесс окна не больше 1 % CPU и до 150 МБ без учёта WebView2. Опрос раз в 2 с.
- **Журналы.** Хранятся последние 20 файлов `engine_*`/`results_*`/`check_*`. Удаляются только файлы с собственным шаблоном имени. Предупреждение, если журнал движка больше 1 ГБ.
- **Кодировка UTF-8,** тексты интерфейса на русском.

## 5. BUILD_MANIFEST и release_guard

- **Форма не меняется:** `{version, build_revision, files{путь: sha256}}`. Для текстовых суффиксов (`release_guard.TEXT_SUFFIXES`) хеш берётся от LF-содержимого, как сейчас. Для остальных (`.ico`) — от сырых байт.
- **В манифест добавляются** все поставляемые новые файлы: `16_DESKTOP.bat`, `app/desktop_engine.py`, новые `app/tests/*`, всё `desktop/**`, кроме `__pycache__`, и `docs/DESKTOP_APP_USER_RU.md`. Хеши изменённых `app/launcher.py`, `app/tests/test_smoke.py`, `app/check_plan_v972.py`, `README_RU.txt` обновляются.
- **Не попадают в манифест и ZIP:** `packaging/**`, `.venv`, `.venv-ui`, `app/data/**`, `app/.env`, `results/**`.
- **Правило EXTRA_MODULE.** Существующее правило `release_guard` (каждый `app/**/*.py` в манифесте) автоматически покрывает `app/desktop_engine.py`. Для `desktop/**/*.py` такое же правило реализует `desktop/release_check.py` при запуске окна: лишний `.py` → отказ запуска окна с текстом `DESKTOP_EXTRA_MODULE`. `release_guard.py` не меняется.
- **Обновление манифеста:** `packaging/desktop/update_manifest.py`. Пересчитывает хеши существующих записей и добавляет явно переданные пути; файлы из исключённых зон отвергает. `version` и `build_revision` по умолчанию не меняет: смена ревизии — это шаг релиза, см. открытые вопросы. После обновления выполняется `.venv\Scripts\python.exe -I app\bootstrap.py verify-release`.

## 6. Автоматическое тестирование без рынка

Интеграционный тест с настоящим движком невозможен без рынка: `main.py` подключается к рыночному потоку. Поэтому настоящий `launcher.start` в тестах **не запускается никогда**. Вместо него — фейки на трёх уровнях.

**Обязательная защита во всех тестах окна** (`fakes.forbid_live`):
- подмена `socket.create_connection` и `socket.socket.connect`: исключение при порте 8188 или 49190;
- подмена `subprocess.Popen`: исключение, если в argv есть `main.py`, `bootstrap.py start` или `desktop_engine.py` без фейка;
- порты для тестовых серверов берутся из диапазона 8210–8219 (первый свободный).

## 7. Как пользователь запускает

- **Новый `16_DESKTOP.bat`** — тот же каркас, что у остальных `.bat`:
  1. `setlocal`, сброс `PYTHONPATH/PYTHONHOME`, `cd /d "%~dp0"`;
  2. проверка `if not exist ".venv\Scripts\python.exe"` → «Run 01_INSTALL.bat first.» и `exit /b 1`;
  3. при первом запуске, если нет `.venv-ui\Scripts\pythonw.exe`: `.venv\Scripts\python.exe -m venv .venv-ui`, затем `.venv-ui\Scripts\python.exe -I -m pip install --require-hashes -r desktop\requirements-desktop.txt`; при ошибке — `goto failed` (`exit /b 1` с паузой);
  4. `start "" ".venv-ui\Scripts\pythonw.exe" -I "%~dp0desktop\app_main.py"` и `exit /b 0`. Консоль закрывается, окно живёт отдельно.
- `app_main.py` сам добавляет ROOT и `app/` в `sys.path`, потому что под `-I` папка скрипта в `sys.path` не попадает.
- `test_smoke.test_v0711_env_and_launchers` фиксирует ровно 15 имён `.bat`. В WP4 туда **добавляется `16_DESKTOP.bat`**, тест обновляется до 16 имён. `test_win314_release` (правило `.venv`, `goto failed`/`exit /b 1`) должен проходить для нового файла.
- Установщик создаёт ярлыки «PumpFun PAPER» в меню «Пуск» и, по выбору, на рабочем столе. Ярлык указывает на `.venv-ui\Scripts\pythonw.exe -I desktop\app_main.py`, рабочая папка — `{app}`.

## Решения по открытым вопросам (02.11.2026, ведущий инженер)

1. **Версия.** Остаётся `v0.7.101.4` / `RUN_REVIEW_V1014`. Её поднимают отдельным релизным шагом, когда собирается ZIP; пакеты работ версию не меняют.
2. **bootstrap.py не меняется.** `app/desktop_engine.py` повторяет его проверки, совпадение закреплено тестом паритета (как в ТЗ).
3. **Обновление на месте разрешено и предпочтительно.** Установщик и портативная сборка ставят новую версию в ту же папку, `app/data`, `app/.env` и `results/` сохраняются. Кампания продолжается под новой версией. Это решает потерю выборки при переходе на новые сборки (01–02.11 так случалось трижды). Перед обновлением бот должен быть остановлен, а `app/data` сохранён через 08_PRESERVE_DATA.
4. **Python.** В MVP нужен установленный Python 3.14. Встроенный CPython — на этапе 5.
5. **Спайк: GO_WITH_WORKAROUNDS** (pywebview 6.2.1, pythonnet 3.2.1 и .NET Framework 4.8.1 на Python 3.14.7 работают). Вариант D не нужен. Обязательные обходы из спайка:
   - короткий путь до `.venv-ui`, иначе `WebView2Loader.dll` и `.pyd` не загружаются. Нужна предпроверка длины пути с понятной ошибкой; junction и symlink не использовать;
   - `private_mode=False` + `storage_path`;
   - для сворачивания в трей — флаг `allow_quit`, а `hide()` вызывается в отдельном потоке;
   - `pystray` запускать через `run_detached()` до `webview.start()`;
   - pid хоста брать из `engine_state.json`, а не из `Popen`.
6. **Журнал хоста.** Пишется в файл без ротации, при размере больше 1 ГБ показывается предупреждение.
7. **Консоль движка.** Только скрытая (`CREATE_NO_WINDOW`). Видимая консоль для отладки — не в MVP.
8. **04 и 05 во время работающей кампании в MVP запрещены.**
9. **Приёмка до конца текущей кампании.** Только фейки и реальная панель на тестовых портах 8210–8219 с копией базы. Сквозной PAPER-прогон из окна — после остановки живой кампании, по согласованию с пользователем.
10. **Демо-режим терминала (`?demo=1`)** требует `samples/*.json`, которых нет в репозитории (спайк, проверка 1c). Для приёмки окна использовать настоящую панель на тестовом порту с копией базы, а не демо-режим.
